# Contributing

Спасибо, что хотите помочь. Коротко о том, как здесь устроено.

## Перед пушем

```bash
./gradlew :app:testDebugUnitTest :app:assembleDebug
```

Обе команды гоняет CI на каждом пуше и PR, так что локальный прогон — способ
узнать проблему за 10 секунд вместо 3 минут в очереди GitHub Actions.

## Стиль

- Kotlin, 4 пробела, имена в стиле текущего файла.
- Комментарии на русском и **с объяснением почему**, а не что. Хороший пример —
  в `NOTES.md` и в блоках над ловушками ffmpeg-kit: там записано не «используем
  `vbr`», а «`cq` чип отвергает с -22, поэтому везде `vbr`».
- Не оставляйте закомментированный код. Если что-то не нужно — удалите.

## CI: три грабли, на которые уже наступали

Всё это стоило по пустому прогону и теперь закреплено в workflow. Ломает
незаметно — видна только в логах Actions.

1. **`gradlew` без бита исполнимости.** На Windows файл попадает в репозиторий
   как `100644`, и на Linux `./gradlew` падает с `Permission denied` (exit 126).
   Лечится один раз: `git update-index --chmod=+x gradlew`. Проверяется так:
   `git ls-files -s gradlew` — должно быть `100755`.
2. **`": "` внутри `run:`.** В YAML двоеточие с пробелом означает новый ключ, и
   workflow отклоняется проверкой схемы: в интерфейсе это «run failed, 0 шагов»,
   в логах — ничего. Строка `run: echo "Готово: файл"` ломает файл; нужен
   блочный скаляр `run: |`.
3. **`android-actions/setup-android` больше не работает.** Он дёргает
   `sdkmanager tools`, а пакет `tools` удалён из репозитория Google. Workflow
   принимает licenses напрямую через cmdline-tools из образа runner, остальное
   доставляет AGP.

Отдельно про кодировку: не переписывайте workflow через `Get-Content`/`Set-Content`
в PowerShell — файлы без BOM читаются как системная ANSI-страница, и русский текст
превращается в мусор. Правьте как текст.

## Локаль тестов

`String.format` без явной локали берёт локаль устройства: на английском системном
языке «31,3 МБ» превращалось в «31.3 МБ», и тесты падали только на CI. Формат в
`TranscodeFormat` зафиксирован явно (`Locale.forLanguageTag("ru")`) — потому что
единицы там русские. Проверить локально с чужой локалью:

```bash
./gradlew :app:testDebugUnitTest --rerun-tasks -Duser.language=en -Duser.country=US
```

## Движок ffmpeg

Движок внутри AAR, и у него есть грабли (одноразовые SAF-URL, Kotlin-API вместо
Java-описания, отсутствие `mediacodec` в некоторых сборках). Прежде чем писать
код вокруг ffmpeg, прочитайте [NOTES.md](NOTES.md) — там уже разобраны известные
проблемы. Новое поведение на устройстве (замеры качества, коды ошибок) туда же.

## Сборка AAR

Меняете кодеки или версию движка — см. [docs/FFMPEG_KIT_NEXT.md](docs/FFMPEG_KIT_NEXT.md)
и не забудьте про `--enable-gpl`: без него не будет `libx264`, и лицензия проекта
станет неверной.

## Ветки

- `dev` — сюда идут все изменения, сюда мержатся PR.
- `release` — проверенное: сюда попадает только то, что готово к публикации.

## Релизы

1. Слить `dev` в `release` (в `release` поднять `versionCode`/`versionName`
   в `app/build.gradle.kts`).
2. Описать изменения в [CHANGELOG.md](CHANGELOG.md).
3. Тег `vX.Y.Z` и пуш — дальше workflow соберёт APK сам.

`versionCode` не переиспользуется никогда: по нему F-Droid и Android понимают,
что это обновление.
